# Feature Specification: 待办工作区：菜单栏、状态栏、图文备注与可迁移存储

**Feature Branch**: `012-todo-workspace`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "添加菜单栏和状态栏，还要有当日待办窗口（也就是当日触发的任务），可以添加图文备注。每个任务触发时，生成一条新的待办。可以查看当日待办和历史待办，进行管理。还有存储要能设置位置，设置后把原来的数据移动到新位置。"

**背景**: 现在只有「今日最小行动」一列清单，没有菜单栏与状态栏，行动不能写备注，也没有历史视图；数据位置写死在 `%LOCALAPPDATA%\ngy-min-action`。本次把「行动」升级为可备注的「待办」，补上当日／历史两个入口，并把数据位置变成可配置、可迁移。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 当日待办与图文备注 (Priority: P1)

用户在「今日」页签看到今天触发的全部待办，点开任意一条即可写文字备注、添加本地图片；备注与图片随待办保存，重启后仍在。

**Why this priority**: 这是需求的核心：待办要能承载「当时怎么做的、遇到了什么」的记录。

**Independent Test**: 打开一条今日待办，输入文字并添加一张图片，关闭后重新打开程序；确认文字与图片缩略图都还在。

**Acceptance Scenarios**:

1. **Given** 今天有触发的任务，**When** 打开「今日」页签，**Then** 每条待办显示任务名、分类名与状态，按当天顺序排列
2. **Given** 打开某条待办的备注，**When** 输入文字并保存，**Then** 列表出现备注标记；重新打开程序后备注仍在
3. **Given** 备注窗口，**When** 通过文件选择或拖拽加入一张受支持的图片，**Then** 图片被复制到数据目录并显示缩略图
4. **Given** 已添加的图片，**When** 点击移除，**Then** 该图片从备注与磁盘中删除，其他图片不受影响
5. **Given** 备注为空，**When** 清空文字并保存，**Then** 备注被清除，待办仍保留

---

### User Story 2 - 历史待办查看与管理 (Priority: P1)

用户切到「历史」页签，按日期倒序翻看过去触发过的待办，查看其备注与图片，并对未结算的待办执行完成／跳过，对已结算的执行撤销。

**Why this priority**: 没有历史就只能看到今天，备注写完也无从回看。

**Independent Test**: 构造前几天的待办，切到历史页签，确认按日期倒序出现；打开备注、结算一条再撤销，状态与数据一致。

**Acceptance Scenarios**:

1. **Given** 数据库里有历史待办，**When** 打开「历史」页签，**Then** 按日期倒序显示，最近的日期在最上面
2. **Given** 历史列表，**When** 点击「更早」，**Then** 载入下一页，页大小固定且不会一次性读出全部数据
3. **Given** 历史中的一条待办，**When** 查看备注，**Then** 文字与图片只读展示，与今日页签同一份数据
4. **Given** 历史中未结算的待办，**When** 执行完成或跳过，**Then** 状态更新，今日页签与计数同步刷新
5. **Given** 历史中已结算的待办，**When** 撤销，**Then** 回到上一状态，复习进度按既有规则回放异常

---

### User Story 3 - 菜单栏与状态栏 (Priority: P2)

窗口顶部有菜单栏，底部有状态栏；菜单提供设置存储位置、切换今日／历史、查看版本与数据位置，状态栏常驻显示数据位置、今日待办数与版本。

**Why this priority**: 菜单栏是存储设置的入口，状态栏让数据位置与当前状态可见；相比待办本身属于外壳能力。

**Independent Test**: 在浅色与深色下打开菜单，逐项点击；状态栏文字完整、不溢出，数据位置与设置一致。

**Acceptance Scenarios**:

1. **Given** 主窗口，**When** 查看顶部，**Then** 菜单栏含「文件」「视图」「帮助」三组
2. **Given** 菜单栏，**When** 选择「视图 → 历史待办」，**Then** 中央区切到历史页签
3. **Given** 状态栏，**When** 数据位置较长，**Then** 路径中间省略并可悬停查看完整路径，不挤占其余信息
4. **Given** 浅色或深色主题，**When** 查看菜单栏与状态栏，**Then** 文字与背景可读，删除类菜单项使用语义危险色
5. **Given** 「帮助 → 关于」，**When** 打开，**Then** 显示版本号与当前数据位置

---

### User Story 4 - 存储位置设置与立即迁移 (Priority: P2)

用户从菜单打开存储设置，选择新目录并确认迁移；程序复制数据库与附件、校验后切换，原位置数据被清理；任何一步失败都保留原位置并给出可执行的错误。

**Why this priority**: 数据在用户手里，能搬走才谈得上可控；但它是低频操作，排在外壳之后。

**Independent Test**: 在临时目录准备数据，迁移到另一个空目录；重启程序，确认数据、备注、图片都来自新位置，原位置已清理。

**Acceptance Scenarios**:

1. **Given** 存储设置窗口，**When** 查看，**Then** 显示当前数据位置与目标位置，目标可用系统目录选择器选取
2. **Given** 选定空目录，**When** 确认迁移，**Then** 复制数据库与 `attachments/`，校验可打开后切换，状态栏路径立即更新
3. **Given** 迁移成功，**When** 重新启动，**Then** 从新位置加载，原位置不再有 `data.db` 与附件
4. **Given** 目标目录已有 `data.db`，**When** 尝试迁移，**Then** 拒绝覆盖并说明原因，原数据不受影响
5. **Given** 复制或校验失败，**When** 迁移中断，**Then** 仍使用原位置，临时文件被清理，错误说明下一步怎么做
6. **Given** 已迁移到新位置，**When** 再次启动第二个实例，**Then** 仍被单实例锁拦截，不会出现两个实例各写一份数据

---

### Edge Cases

- **今天没有触发任何任务**：今日页签显示空状态与新建任务提示，不出现空列表框架
- **备注过长**：超出上限时拒绝保存并提示上限，不静默截断
- **图片格式不支持或损坏**：在加入时校验并拒绝，错误指出文件与支持格式
- **图片过大**：超过单张大小上限时拒绝，不复制进数据目录
- **图片文件被外部删除**：备注仍可打开，缺失的图片显示占位与文件名，不 panic
- **删除任务或目标**：历史待办与备注保留，不因上层对象删除而消失
- **跨日时备注窗口开着**：保存仍作用于原待办，今日列表与计数切到新的一天
- **迁移到相同目录或源目录的子目录**：拒绝并说明
- **迁移到不可写目录**：拒绝并说明，原位置继续可用
- **迁移后旧目录清理失败**：迁移仍算成功，提示残留路径，不阻塞继续使用
- **旧库升级**：从 schema 2 升级到 3 时保留既有行动，只新增备注与图片结构
- **历史页签翻页到底**：显示「没有更早的待办」，不重复加载

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主窗口 MUST 提供菜单栏，至少含「文件」「视图」「帮助」三组；「文件」含存储位置设置，「视图」含今日／历史切换，「帮助」含版本与数据位置
- **FR-002**: 主窗口 MUST 提供底部状态栏，显示当前数据位置、今日待办数与程序版本；长路径不得挤压其他信息
- **FR-003**: 中央区 MUST 提供「今日」「历史」两个页签，切换不丢失各自滚动位置与筛选状态
- **FR-004**: 今日页签 MUST 列出当天触发的全部待办，沿用「一个任务一天最多一条」的唯一约束与幂等生成
- **FR-005**: 每条待办 MUST 支持文字备注；保存后持久化，清空后删除备注
- **FR-006**: 每条待办 MUST 支持附件图片，可通过系统目录／文件选择器或拖拽文件加入；图片 MUST 复制进数据目录，不引用外部路径
- **FR-007**: 图片 MUST 在加入时校验格式与大小；仅接受 PNG、JPEG、WebP、BMP，单张不超过 10 MiB
- **FR-008**: 备注窗口 MUST 显示图片缩略图与原始文件名，支持逐张移除；移除同时删除磁盘副本
- **FR-009**: 历史页签 MUST 按日期倒序展示历史待办，采用固定页大小分页，不一次性读出全部行
- **FR-010**: 历史待办 MUST 可查看备注与图片，并可执行完成、跳过与撤销，规则与今日页签一致
- **FR-011**: 菜单与状态栏 MUST 在两套主题下可读；危险动作 MUST 使用语义危险色
- **FR-012**: 用户 MUST 能通过系统目录选择器设置新的数据位置；确认后立即迁移，无需重启
- **FR-013**: 迁移 MUST 复制数据库与 `attachments/`，验证新库可打开且完整性检查通过后才切换，并原子写入位置配置
- **FR-014**: 迁移失败 MUST 保留原位置与原数据，清理目标位置的临时产物，并给出可执行的错误说明
- **FR-015**: 迁移成功后 MUST 清理原位置的数据文件；清理失败只提示，不影响继续使用
- **FR-016**: 单实例锁 MUST 与数据位置解耦，无论数据目录设到哪里都只允许一个实例
- **FR-017**: 数据 MUST 完全离线存放与读取，不发起网络请求；图片只在本地解码
- **FR-018**: 从 schema 2 升级到 3 MUST 保留既有目标、分类、任务、行动与复习进度；新结构只做增量变更
- **FR-019**: 本 feature MUST NOT 改动任务调度、每日上限、提醒判定与复习曲线规则
- **FR-020**: 新增依赖 MUST 通过 `cargo audit`，且不引入运行时网络能力

### Key Entities

- **待办**：现有行动（action）的用户可见形态，包含任务、日期、类型、状态、顺序、备注文字
- **图片附件**：属于某条待办的文件记录，包含文件名、原始文件名、大小、加入时间；磁盘副本位于数据目录的 `attachments/<待办 ID>/`
- **位置配置**：独立于数据目录的启动配置，记录自定义数据位置；缺省时使用用户本地数据目录下的默认路径
- **历史分页**：按日期倒序的待办窗口，页大小固定，带「更早」游标

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 今日页签能显示当天全部待办；备注与图片在重启后仍可读取，附件文件位于当前数据目录内
- **SC-002**: 历史页签首次加载不超过固定页大小，连续翻页可覆盖全部历史，且无重复行
- **SC-003**: 菜单栏与状态栏在浅色、深色下各截图一次，文字可读、长路径不溢出
- **SC-004**: 迁移到空目录后，新位置含 `data.db` 与完整 `attachments/`，重启后从新位置加载；原位置数据被清理
- **SC-005**: 迁移失败场景（目标已有数据、不可写、校验失败）均保留原位置，程序可继续使用
- **SC-006**: 新增图片、备注、历史与迁移逻辑均有先失败后通过的测试；全部 CI 门禁通过

## Assumptions

- **待办模型**（已确认）：沿用每天每任务一条，不修改 `UNIQUE(task_id, on_date)`；「触发」指任务当天到期生成待办，重复刷新保持幂等
- **图片方式**（已确认）：新增 `rfd`（目录／文件选择）、`egui_extras`（image 加载）、`image`（解码与格式校验）；图片复制进数据目录，完全离线
- **存储迁移**（已确认）：目录选择器 + 立即迁移；复制、校验、写配置、切换后清理原位置，失败保留原位置
- **界面形态**（已确认）：中央区「今日 / 历史」页签，顶部菜单栏，底部状态栏；现有顶栏保留为工具条
- **备注范围**：文字备注为纯文本，不解析 Markdown；图片只做缩略图展示，不做裁剪、旋转或标注
- **历史范围**：历史待办只读展示备注，但允许完成／跳过／撤销；不提供删除待办或批量清理
- **兼容性**：数据位置配置在默认目录下的独立文件；移动数据不改变数据库结构版本之外的行为
