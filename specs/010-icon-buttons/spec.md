# Feature Specification: 用图标替换操作按钮

**Feature Branch**: `010-icon-buttons`

**Created**: 2026-11-05

**Status**: Draft

**Input**: User description: "把按钮换成图标。"

**背景**: 009 落地后界面仍以中文文字按钮为主：顶栏有「统计」，任务行有「改名」「暂停」「重置复习」与删除按钮，各弹窗底部有「保存」「取消」「删除」「关闭」等。窄窗口下这些文字按钮挤占空间，任务行尤其密集。用户希望改用图标，让操作区更紧凑、更接近常见桌面工具条，同时保留原有行为与可读性。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 操作按钮改为图标 (Priority: P1)

用户打开主界面与任一弹窗，原先的文字操作按钮显示为图标，点击后的行为与替换前完全一致。

**Why this priority**: 这是需求本身：把按钮换成图标是本 feature 的核心交付物。

**Independent Test**: 逐屏对比替换前后的按钮位置与点击结果：任务行的改名、暂停、重置复习、删除，顶栏的统计，弹窗的保存、取消、删除、关闭，均能在图标状态下完成原有操作。

**Acceptance Scenarios**:

1. **Given** 主界面已载入任务，**When** 查看任务行，**Then** 改名、暂停、重置复习与删除均显示为图标，不再显示中文文字标签
2. **Given** 任一弹窗打开，**When** 查看底部操作区，**Then** 保存、取消、删除、关闭等按钮显示为图标，位置与顺序不变
3. **Given** 点击任一图标，**When** 观察结果，**Then** 与替换前对应文字按钮的行为一致，包括危险操作仍弹出二次确认

---

### User Story 2 - 图标仍然可理解 (Priority: P2)

图标不能让人猜功能：悬停时给出与原文一致的中文说明；主题切换、空状态、错误提示这些需要文字表达的信息不被图标化。

**Why this priority**: 纯图标的最大风险是丧失可发现性；没有提示会让改名、重置复习这类低辨识度操作变成盲点。

**Independent Test**: 逐个悬停图标，核对提示文案；确认主题下拉、表单标签、统计数值、空状态与错误提示仍是文字。

**Acceptance Scenarios**:

1. **Given** 任一图标按钮，**When** 鼠标悬停，**Then** 显示与替换前中文标签一致的提示
2. **Given** 顶栏的主题选择入口，**When** 查看该控件，**Then** 仍显示当前选择的文字，不被图标替代
3. **Given** 空库、校验失败或存储出错，**When** 查看对应提示，**Then** 仍是文字说明，不退化为一个图标
4. **Given** 危险操作图标，**When** 点击，**Then** 仍进入原二次确认流程，且提示文案保留

---

### User Story 3 - 图标在两套主题下都清晰 (Priority: P3)

图标沿用 009 的语义色与间距令牌，浅色与深色下都不出现缺字、糊成一团或与背景融为一体的情况。

**Why this priority**: 主题是上一个 feature 刚建立的能力，不能被图标破坏；但相比前两项，它属于质量约束而非新功能。

**Independent Test**: 浅色与深色各截一张主界面与全部弹窗，逐个检查图标形状、颜色、间距与命中区域。

**Acceptance Scenarios**:

1. **Given** 浅色或深色主题，**When** 查看所有图标，**Then** 形状完整可辨，无缺字符号，颜色沿用普通／警告／危险语义色
2. **Given** 窄窗口，**When** 查看任务行与弹窗操作区，**Then** 图标不重叠、不溢出，命中区域不小于替换前的文字按钮
3. **Given** 切换主题，**When** 查看已打开的弹窗，**Then** 图标与主界面同步换色

---

### Edge Cases

- **内置字体缺字**：若某个候选符号在界面里显示成缺字占位符，必须换成已验证可用的符号或由界面代码绘制的简单图形，不能留豆腐块
- **低辨识度操作**：改名、重置复习这类操作靠形状不易判断，必须用提示文案兜底
- **危险操作**：删除与重置复习的图标要与非危险操作区分，且二次确认不能被绕过
- **窄窗口与缩放**：图标按钮不能被挤压、不能与相邻控件重叠
- **主题选择**：三态下拉必须保留文字，不图标化
- **错误与空状态**：文字信息不图标化；错误色仍来自语义令牌
- **行为不变**：图标替换不得改任务状态、复习进度、每日上限、统计结果与主题偏好

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 范围内的操作按钮 MUST 以图标呈现，MUST NOT 再显示中文文字标签
- **FR-002**: 每个图标按钮 MUST 有悬停提示，文案与替换前的中文标签一致
- **FR-003**: 本 feature MUST NOT 引入图标库、自定义字体、图片文件或网络资源；图标 MUST 由界面现有能力呈现
- **FR-004**: 图标颜色 MUST 沿用 009 的语义令牌，MUST NOT 新增颜色字面量
- **FR-005**: 点击行为、二次确认、草稿保留、错误提示与替换前 MUST 完全一致
- **FR-006**: 危险操作的图标 MUST 与普通操作在视觉上可区分
- **FR-007**: 图标按钮的命中区域 MUST 不小于被替换的文字按钮
- **FR-008**: 主题选择入口、表单标签、统计数值、空状态与错误提示 MUST 保留文字
- **FR-009**: 每个图标 MUST 在浅色与深色两套主题下经 GUI 确认可辨、无缺字、无溢出
- **FR-010**: 本 feature MUST NOT 改动业务数据、存储结构、调度或统计逻辑
- **FR-011**: 界面 MUST 保持完全离线，`Cargo.toml` MUST NOT 因本 feature 新增依赖
- **FR-012**: 图标与间距 MUST 集中定义，MUST NOT 在各视图里散落重复的形状字面量

### Key Entities

- **操作按钮**：任务行的改名、暂停、重置复习、删除；顶栏的统计；各弹窗的保存、取消、删除、关闭、确认等
- **图标定义**：形状、语义（普通／主要／危险）、命中区域与悬停文案的集中映射
- **悬停提示**：图标与原有中文标签之间的对应关系，是图标可发现性的保证
- **现有界面对象**：主界面、任务行、今日清单、六个弹窗、空状态与错误提示

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 范围内每个按钮在浅色与深色两套主题下逐个截图核对：无文字残留、无缺字符号、无重叠或溢出
- **SC-002**: 每个图标的悬停提示与替换前中文标签逐项一致，无遗漏
- **SC-003**: 既有自动化测试全部保持通过，新增用例覆盖图标渲染与点击行为不变
- **SC-004**: `Color32::` 仍只出现在 009 的令牌文件；`Cargo.toml` 无新增依赖；所有 `.rs` 低于 700 行硬上限

## Assumptions

- **替换范围**：所有可独立表达的操作按钮（含任务行、顶栏统计、弹窗操作区）；主题三态下拉、表单标签、统计数值、空状态与错误提示保留文字
- **图标来源**：使用现有内置能力可呈现的符号或简单图形，不引入图标库、字体、图片与网络资源；009 的「完全离线」约束继续有效
- **可发现性**：每个图标都保留与原文一致的悬停提示
- **尺寸**：图标按钮的命中区域不小于原文字按钮，不改变任务行列对齐与弹窗操作区顺序
- **沿用主题**：继续复用 009 的语义色、间距与字号令牌，不新建配色体系
- **不新增依赖**：沿用现有界面框架与字体，不为图标引入 crate
