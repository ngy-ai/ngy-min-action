# Feature Specification: 复习统计与回顾

**Feature Branch**: `008-review-stats`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "行动表里每天完成/跳过/过期都记着，但界面上一个汇总都看不到，坚持了多久、完成率多少全靠猜。"

**背景**: `actions` 表按天记录了每条行动的结果，`review_progress` 也记了每个任务走到第几级。但这些数据只用于调度，界面从不汇总。用户无法回答「这周坚持得怎么样」「有多少任务已经巩固」。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 看近 30 天的完成率 (Priority: P1)

点「统计」，看到近 30 天已结算行动的完成率，以及完成、跳过、过期各自的条数。

**Why this priority**: 这是唯一能回答「最近有没有在推进」的数字，也是其余统计里最有行动价值的一个。

**Independent Test**: 造 6 条已结算行动（4 完成、1 跳过、1 过期）→ 完成率显示 67%，分项分别是 4 / 1 / 1。

**Acceptance Scenarios**:

1. **Given** 近 30 天有 4 完成、1 跳过、1 过期，**When** 打开统计，**Then** 显示完成率 67%，分项 4 / 1 / 1
2. **Given** 完成数为 0 但有过期记录，**When** 打开统计，**Then** 完成率显示 0%，不显示 `NaN` 或 `--`
3. **Given** 近 30 天内没有任何已结算行动，**When** 打开统计，**Then** 显示「近 30 天还没有已结算的行动」，其余分项不展示 0 值

---

### User Story 2 - 看连续完成天数 (Priority: P2)

看到当前连续完成天数与历史最长连续天数。

**Why this priority**: 连续天数是最直接的坚持反馈；但它依赖对「哪天算达成」的定义，所以排在完成率之后。

**Independent Test**: 造 3 天都有完成记录 → 当前连续 3 天；隔一天全是跳过 → 当前归零、最长仍为 3。

**Acceptance Scenarios**:

1. **Given** 连续 3 天每天都有完成，**When** 打开统计，**Then** 当前连续 3 天、最长 3 天
2. **Given** 第 4 天全部跳过，**When** 打开统计，**Then** 当前连续 0 天、最长 3 天
3. **Given** 某天没有任何行动（没生成），**When** 该天夹在两组连续达成之间，**Then** 不视为中断
4. **Given** 今天有行动但还一条没完成，**When** 打开统计，**Then** 今天不计入当前连续，也不算中断

---

### User Story 3 - 看复习进度分布 (Priority: P3)

看到任务按「未开始 / 学习中 / 已巩固」分组各有多少个。

**Why this priority**: 它回答「我的任务库健康吗」，但不如前两项有每日反馈感。

**Independent Test**: 造 5 个任务（2 个 level 0、2 个 level 1–5、1 个 graduated）→ 分布显示 2 / 2 / 1，合计 5。

**Acceptance Scenarios**:

1. **Given** 5 个任务分布在三个阶段，**When** 打开统计，**Then** 分组计数为 2 / 2 / 1，合计等于任务总数
2. **Given** 已软删除的任务，**When** 统计分布，**Then** 不计入任何分组

---

### Edge Cases

- **空库**：显示统一的空状态，不显示任何 0/0 或除零结果
- **只有 pending 行动**：不计入完成率分母（未结算），显示空状态
- **全部过期**：完成率 0%，过期数等于总数
- **任务被删除后**：它的过期行动仍计入完成率分母，但不再计入阶段分布
- **跨过没有行动的日子**：连续天数不中断
- **今天尚未完成**：今天既不贡献连续天数，也不打断它
- **统计期间数据变化**：统计为只读，不改任何行

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主界面 MUST 提供「统计」入口，打开后展示统计面板
- **FR-002**: 面板 MUST 展示近 30 天（含今天）已结算行动的完成率，分母为完成 + 跳过 + 过期
- **FR-003**: 面板 MUST 分别展示完成、跳过、过期三条分项计数
- **FR-004**: 面板 MUST 展示当前连续天数与历史最长连续天数
- **FR-005**: 连续天数 MUST 按「当天有已完成行动即达成」判定；「当天有行动但零完成」中断；「当天无任何行动」跳过；今天是例外，零完成不算中断
- **FR-006**: 面板 MUST 展示任务按未开始（level 为 0）、学习中（level 大于 0 且未巩固）、已巩固三档的计数
- **FR-007**: 阶段分布 MUST 排除已软删除的任务；行动统计 MUST 保留已删除任务的历史行动——删除任务会把它的未完成行动转为过期，这是真实发生过的事实，抹掉会让统计失真
- **FR-008**: 无任何已结算行动时 MUST 显示空状态，MUST NOT 显示 `0/0` 或 `NaN`
- **FR-009**: 统计 MUST 只读，MUST NOT 写入任何数据
- **FR-010**: 本 feature MUST NOT 修改持久化结构

### Key Entities

- **已结算行动**: `status` 为 `done`、`skipped` 或 `expired` 的行动；`pending` 与 `deferred` 不计
- **达成日**: 当天至少有一条 `done` 行动的日期
- **中断日**: 当天有行动但没有任何 `done`，且该日期早于今天
- **复习阶段**: 未开始（level 0）、学习中（1 至序列末尾）、已巩固（graduated）

## Success Criteria *(mandatory)*

- **SC-001**: 完成率与三条分项计数与造数逐一吻合，误差 0
- **SC-002**: 连续天数在「中间缺一天达成」时归零、在「中间缺一天行动」时不断，两种情形都被用例覆盖
- **SC-003**: 空库与只有 pending 两种情形都显示空状态，不出现除零结果
- **SC-004**: 打开统计不产生任何写入（关闭后数据库行数不变）

## Assumptions

- **固定 30 天窗口**：不做时间范围切换，避免引入日期选择器
- **不做图表**：先用文字与数字，条形图留给以后
- **不统计单个目标**：本期只做全局，按目标分组是下一个 feature
- **连续天数全量计算**：不受 30 天窗口限制，最长连续取历史全量
