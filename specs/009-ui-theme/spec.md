# Feature Specification: 界面美化与明暗主题

**Feature Branch**: `009-ui-theme`

**Created**: 2026-11-05

**Status**: Draft

**Input**: User description: "美化界面，支持 dark/light 主题。"

**背景**: 界面目前使用默认外观：只有「已顺延」与错误文案两处临时颜色，任务行、弹窗、空状态之间没有统一的间距与层级。用户长时间盯着屏幕，需要一套可切换、可记忆的明暗外观，以及更清晰、更一致的视觉层级。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 切换明暗主题 (Priority: P1)

用户从主界面一键在浅色与深色之间切换，主界面与所有已打开的弹窗立即整体换色，不出现新旧配色混杂。

**Why this priority**: 这是本 feature 的核心价值：深色环境下的可读性，以及用户对界面外观的控制权。

**Independent Test**: 打开主界面并打开「统计」面板 → 切换主题 → 主界面、今日清单、统计面板的文字、背景、按钮、进度条同时换到目标主题。

**Acceptance Scenarios**:

1. **Given** 当前为浅色，**When** 切到深色，**Then** 顶栏、结构树、今日清单、统计面板与所有弹窗在一个重绘周期内全部变为深色
2. **Given** 弹窗（重命名／删除／频率／耗时／统计）处于打开状态，**When** 切换主题，**Then** 弹窗与主界面同步换色，弹窗不关闭、不丢失草稿
3. **Given** 切换主题，**When** 对比切换前后的界面，**Then** 不存在仍使用旧主题颜色的文字或控件

---

### User Story 2 - 主题选择被记住 (Priority: P2)

用户选择「浅色」「深色」或「跟随系统」后，关闭并重新打开程序仍然是这个选择；选「跟随系统」时，系统明暗变化后界面随之切换。

**Why this priority**: 每次启动都重选一遍会让主题功能形同虚设；跟随系统则是桌面程序的默认预期。

**Independent Test**: 选择深色 → 退出 → 重新启动 → 界面直接以深色出现，无闪烁；切到「跟随系统」后改变系统主题 → 界面在数秒内跟随。

**Acceptance Scenarios**:

1. **Given** 选择了深色，**When** 重启程序，**Then** 首帧即为深色，不出现先浅后深的闪烁
2. **Given** 选择了「跟随系统」，**When** 系统在浅色与深色之间切换，**Then** 界面在 2 秒内跟随，且不需要重启
3. **Given** 首次启动且没有任何偏好记录，**When** 打开程序，**Then** 默认按系统当前明暗显示
4. **Given** 偏好记录为无法识别的值，**When** 启动程序，**Then** 回退到「跟随系统」，不报错、不崩溃

---

### User Story 3 - 视觉层级统一 (Priority: P3)

主界面、任务行与各弹窗采用统一的配色令牌、间距与字号层级；主要操作、次要操作与危险操作在视觉上可区分，空状态与错误提示不再各写各的。

**Why this priority**: 主题换色只是第一步；没有统一的令牌与层级，换色后界面仍会显得零散。但它不如前两项有那么直接的功能价值，所以排在最后。

**Independent Test**: 逐屏检查主界面、结构树、今日清单、五个弹窗与空状态：同类元素间距一致，主要／次要／危险操作外观可区分，错误与警告使用语义色。

**Acceptance Scenarios**:

1. **Given** 任意界面，**When** 查看操作按钮，**Then** 主要操作、次要操作与危险操作各有可区分的样式，且危险操作仍需二次确认
2. **Given** 空库或空分类，**When** 查看主界面与今日清单，**Then** 空状态使用统一的弱化样式，不出现孤立的默认颜色文本
3. **Given** 校验失败或存储出错，**When** 查看错误提示，**Then** 使用统一的语义错误样式，在两种主题下都清晰可读
4. **Given** 任务行包含名称、频率、耗时、状态与操作，**When** 在两种主题下查看，**Then** 各列对齐一致，长名称截断行为一致

---

### Edge Cases

- **首次启动无偏好**：按系统明暗显示，不写入任何业务数据
- **系统主题在运行中变化**：仅在「跟随系统」下实时跟随；手动选择浅色或深色时不跟随
- **弹窗打开时切换主题**：弹窗内容与草稿保持不变，仅换色
- **偏好记录损坏或未知**：回退「跟随系统」，记录一条警告，不阻塞启动
- **切换主题时的错误提示**：错误文案在浅色与深色下都必须达到对比度要求，不能被背景吞掉
- **已顺延提示与「已巩固」弱化文字**：语义色在两种主题下都要重新取值，不能沿用单一亮色
- **同时打开多个弹窗**（如重命名与统计）：切换主题后全部同步，不残留旧色
- **主题切换不影响业务**：行动状态、复习进度、每日上限、统计结果均不变

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主界面 MUST 提供主题入口，至少覆盖「跟随系统」「浅色」「深色」三种选择
- **FR-002**: 主题选择 MUST 立即生效，覆盖主界面、结构树、今日清单与所有已打开的弹窗，无需重启
- **FR-003**: 主题选择 MUST 持久化，重启后恢复；持久化不得改变任何业务数据
- **FR-004**: 首次启动且无偏好时 MUST 默认「跟随系统」
- **FR-005**: 「跟随系统」时，系统明暗变化后界面 MUST 在 2 秒内跟随
- **FR-006**: 两套主题下，正文文字与背景的对比度 MUST ≥ 4.5:1，大字号文字 MUST ≥ 3:1
- **FR-007**: 颜色、间距与字号 MUST 集中定义为可复用的令牌；界面代码 MUST NOT 散落颜色字面量（语义色同样走令牌）
- **FR-008**: 主要操作、次要操作与危险操作 MUST 有可区分的视觉样式；危险操作 MUST 保留二次确认
- **FR-009**: 结构树、任务行、今日清单与统计面板在两种主题下 MUST 保持对齐、可读与一致的截断行为
- **FR-010**: 空状态与错误提示 MUST 使用统一的语义样式，不得直接沿用默认的高饱和颜色
- **FR-011**: 主题切换、偏好读取与写入 MUST NOT 改变行动、任务、复习进度、每日上限与统计结果
- **FR-012**: 启动时 MUST 直接应用已保存偏好，MUST NOT 出现先亮后暗或先暗后亮的闪烁
- **FR-013**: 本 feature MUST NOT 修改既有业务表结构；如需要新增偏好存储，MUST 只增不改
- **FR-014**: 界面 MUST NOT 引入网络资源、自定义字体文件或图标库，保持完全离线

### Key Entities

- **主题偏好**: 用户在「跟随系统」「浅色」「深色」之间的选择，以及该选择的来源（默认、手动）
- **配色令牌**: 背景、表面、边框、正文、弱化文字、强调色、成功、警告、危险等语义槽位，每个槽位在浅色与深色下各有一个取值
- **间距与字号令牌**: 用于统一面板内边距、控件间距、标题与正文层级的少量标量
- **现有界面对象**: 主界面、结构树、今日清单、任务行、五个弹窗、空状态、错误提示

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 浅色与深色两套主题下，主界面与五个弹窗的文字对比度全部达到 4.5:1（大字 3:1），逐项检查无例外
- **SC-002**: 一次点击即可完成主题切换，界面在 100ms 内完成重绘；切换后不存在使用旧主题颜色的控件
- **SC-003**: 三种偏好各验证一次重启恢复；首帧即为目标主题，无可见闪烁
- **SC-004**: 界面代码中不再出现散落的颜色字面量（令牌定义文件除外），可用文本检索复核
- **SC-005**: 既有自动化测试全部保持通过，业务数据与行动状态在主题切换前后完全一致

## Assumptions

- **入口位置**：主题切换放在顶栏，与「统计」同一区域，不单独做设置页
- **默认策略**：首次启动「跟随系统」；手动选择后覆盖，直到用户改回
- **持久化方式**：复用现有本地设置存储，不新增配置文件、环境变量或命令行参数
- **美化范围**：限于配色、间距、字号层级、操作分组、空状态与错误提示；不调整信息架构与主布局
- **不引入资源**：沿用内置字体与纯文本控件，不引入图标库、自定义字体或网络资源
- **不做过渡动画**：首版直接切换配色，动画留待以后
- **深色与浅色共用布局**：两种主题只在颜色、对比度与必要的间距上不同，窗口尺寸与面板结构保持一致
