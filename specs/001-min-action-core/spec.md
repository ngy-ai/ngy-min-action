# Feature Specification: 最小行动管理系统（每日最小行动闭环）

**Feature Branch**: `001-min-action-core`

**Created**: 2026-11-01

**Status**: Draft

**Input**: User description: "这个项目是最小行动管理系统，主要用来帮助用户生成每天的最小行动任务。包括分类、任务。例如，用户的第一个目标是学习英语，下面分为语法、单词、听力、口语、阅读、写作等；然后为口语写下任务：每周学习一个连读，然后按遗忘曲线复习，系统自动生成任务，并在每天进行提示。"

**Clarifications**:

- Q1 每日上限 → 采用「全局上限 + 每任务上限」双重约束
- Q2 每日提示 → PC 桌面程序常驻运行，跨多天不关机时每天弹出一次置顶窗口

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 建立目标、分类与任务三层结构 (Priority: P1)

用户有一个长期目标「学习英语」，把它写成系统里的一个目标；在这个目标下建立六个分类：语法、单词、听力、口语、阅读、写作；然后在「口语」分类下写下一个任务「每周学习一个连读」，频率为每周一次。用户可以随时查看这三层结构，也能修改或删除它们。

**Why this priority**: 这是整个系统的输入面。没有结构化的目标、分类与任务，后续的每日生成与复习调度都无从谈起；而只有这一层，用户也已经得到一个可长期维护的行动清单。

**Independent Test**: 从空数据开始，依次创建「目标 → 分类 → 任务」，再逐层查看，即可验证三层结构被正确建立、归属关系正确、非法输入被拒绝。

**Acceptance Scenarios**:

1. **Given** 系统中没有任何数据，**When** 用户创建目标「学习英语」，**Then** 该目标出现在目标列表中，且为唯一目标
2. **Given** 已存在目标「学习英语」，**When** 用户在该目标下依次创建「语法」「单词」「口语」等分类，**Then** 每个分类都归属于「学习英语」，并能在该目标的详情中按创建顺序看到
3. **Given** 同一目标下已存在分类「口语」，**When** 用户再次在该目标下创建名为「口语」的分类，**Then** 系统拒绝创建并说明「同一目标下分类名称必须唯一」，原有数据不变
4. **Given** 已存在分类「口语」，**When** 用户在「口语」下创建任务「每周学习一个连读」，**Then** 该任务出现在「口语」分类下，并显示其频率为每周一次
5. **Given** 用户输入空白名称或只含空格的名称，**When** 提交创建，**Then** 系统拒绝创建，说明哪一项输入不合法、期望什么、如何修正，且不留下任何数据
6. **Given** 已存在带分类与任务的目标，**When** 用户删除该目标并确认，**Then** 其下分类、任务以及未完成的行动一并删除，已完成的历史记录保留，系统在确认步骤中明确告知影响范围

---

### User Story 2 - 每天自动得到一份可执行的最小行动清单 (Priority: P1)

用户每天看到的不是整个任务库，而是「今天只需要做的几件小事」。系统根据任务的频率与复习计划自动生成当天的行动，并且总量受双重上限约束：整体有上限，单个任务每天也只占一条；超出上限的行动顺延，不会一次性堆到用户面前。

**Why this priority**: 这是产品的核心价值——把「我有一堆要学的东西」压缩成「今天只做这几件」，降低启动成本。少了这一步，系统只是一个任务清单，不是最小行动系统。

**Independent Test**: 给定一组已配置频率的任务，查看任意指定日期应生成的行动集合：条数不超过全局上限、同一任务当天最多一条、重复查看同一天结果完全一致、超出上限的部分有明确的顺延去向。

**Acceptance Scenarios**:

1. **Given** 存在频率为「每天」的任务「背 10 个单词」，**When** 用户查看 2026-11-02 的行动清单，**Then** 清单中包含该任务对应的一条常规行动
2. **Given** 存在频率为「每周一次」的任务「每周学习一个连读」，且它上次生成行动是 2026-11-02，**When** 用户查看 2026-11-03 至 2026-11-08 的清单，**Then** 这些日期都不包含该任务的常规行动
3. **Given** 同一天有 8 条待生成的行动、全局上限为 5，**When** 用户查看当天清单，**Then** 只列出 5 条，其余 3 条顺延到之后的日期，且系统明确显示「已顺延 3 条」
4. **Given** 全局上限为 5 且只有一个任务满足生成条件，**When** 用户查看当天清单，**Then** 该任务最多占 1 条，不会因为是唯一任务而被重复填充到 5 条
5. **Given** 用户已查看过 2026-11-02 的清单，**When** 用户关闭并重新打开程序后再次查看 2026-11-02，**Then** 清单内容与条数完全一致，不产生重复行动
6. **Given** 用户连续 10 天没有使用系统，**When** 用户再次打开程序，**Then** 系统只生成当天可容纳的行动，不把 10 天的积压一次倾倒出来
7. **Given** 存在已被暂停的任务，**When** 用户查看任意日期清单，**Then** 该任务不产生任何常规行动或复习行动
8. **Given** 用户本地时间跨过 00:00，**When** 用户查看「今天」，**Then** 系统以本地日期为准切换到新的一天

---

### User Story 3 - 完成行动后由遗忘曲线接管复习 (Priority: P2)

用户完成「每周学习一个连读」这条行动后，系统自动按遗忘曲线（间隔逐级拉长）安排下一次复习日，届时生成一条复习行动。用户能查看某个任务当前复习到第几级、下次什么时候复习，也能在觉得需要从头再来时重置进度。

**Why this priority**: 复习是把一次学习转成长期记忆的机制，也是「按遗忘曲线复习」这一明确诉求的落点。它依赖前面的生成链路，但即便尚未实现，前两个故事也已构成可用产品。

**Independent Test**: 标记一条行动完成，检查该任务的复习进度与下次复习日期；在相应日期查看清单，确认出现复习行动；再验证跳过与重置两种路径不污染复习序列。

**Acceptance Scenarios**:

1. **Given** 一条常规行动在 2026-11-02 被标记完成，**When** 用户查看该任务的复习进度，**Then** 显示已进入第 1 级复习，下次复习日为 2026-11-03
2. **Given** 某任务的复习日已到，**When** 用户查看当天清单，**Then** 清单中包含一条标记为复习的行动，并注明是第几级复习
3. **Given** 用户在复习日把复习行动标记完成，**When** 用户查看复习进度，**Then** 复习级别递增一级，下次复习日按遗忘曲线序列后移
4. **Given** 用户跳过了一条复习行动，**When** 用户查看次日的清单，**Then** 该任务的复习行动因复习日未推进而在次日重新到期，且复习进度没有推进
5. **Given** 用户把某任务的复习进度重置，**When** 用户查看复习进度，**Then** 显示为未开始复习，下次复习日以最近一次完成行动重新计算
6. **Given** 用户误标了完成，**When** 用户撤销该标记，**Then** 复习进度回退到标记前的级别与下次复习日
7. **Given** 某个任务已走完遗忘曲线序列，**When** 用户查看复习进度，**Then** 显示为「已巩固」，不再自动生成复习行动，直到用户手动重置

---

### User Story 4 - 常驻运行，每天弹出一次最前端提示 (Priority: P3)

用户在电脑上启动这个程序后，即使连续多天不关机、不重启，程序也一直待在后台。每到新的一天，程序弹出一个置顶窗口，停在其他所有窗口之上，告诉用户今天还有几条最小行动没做。用户关掉窗口就完成当天提示，同一天内不会再次被打扰。

**Why this priority**: 提示决定了「自动生成」能否变成「真的去做」。它是增值项而非基础项——没有提示，用户仍可主动查看清单并完成闭环。

**Independent Test**: 让程序在同一进程内连续跨越多天（可用系统时间或测试用日期推进模拟），确认每跨一天恰好弹出一次窗口、窗口位于最前端、关闭窗口后当天不再弹出、跨日后重新生效。

**Acceptance Scenarios**:

1. **Given** 程序已在后台运行且当天尚未提示过，当天有 3 条未完成行动，**When** 本地日期进入这一天（或程序当天首次就绪），**Then** 弹出一个置顶窗口，显示今天有 3 条未完成行动
2. **Given** 提示窗口已经弹出过并被用户关闭，**When** 用户在同一天继续使用电脑，**Then** 不再弹出第二个提示窗口
3. **Given** 提示窗口正显示着，**When** 程序收到其他交互请求，**Then** 不叠加第二个提示窗口
4. **Given** 程序连续运行且用户始终不重启电脑，**When** 本地日期推进到第二天、第三天，**Then** 每个新的一天都恰好弹出一次提示窗口
5. **Given** 跨日时刻电脑处于系统睡眠或程序被挂起，**When** 系统恢复或程序恢复运行，**Then** 立即补发当天的提示窗口，且当天仍然只弹一次
6. **Given** 当天没有未完成的行动，**When** 进入新的一天，**Then** 不弹出提示窗口，程序保持静默
7. **Given** 提示窗口处于最前端，**When** 用户点击窗口中的「查看今日清单」，**Then** 直接进入今天的行动清单，可逐条标记完成
8. **Given** 用户此前已关闭过当天的提示窗口，**When** 用户重启程序，**Then** 当天不再弹窗，直到下一个本地日

---

### Edge Cases

- 用户为同一任务在同一天重复触发生成：不得产生重复行动，也不得因重复触发而推进任何计数
- 全局上限被复习行动占满，导致常规行动长期顺延：系统必须让用户看见「有行动在被持续顺延」，而不是静默吞掉
- 一个任务同时在语义上「该生成常规行动」又「该生成复习行动」：同一天该任务只上线一条行动，避免自我叠加
- 任务在暂停期间错过多个应生成日：恢复后不补生成暂停期间的行动，只从恢复之日起算
- 删除分类时其下仍有任务与未完成行动：与删除目标相同，需要先确认影响范围，再级联清理
- 修改任务频率为更稀疏或更密集：已生成的历史行动不变，只影响之后日期的生成判断
- 名称中出现换行、制表符、控制字符或极长字符串：在输入边界被拒绝或被清理，不能破坏界面布局或伪造界面元素
- 首次使用、完全空数据：进入今日清单不报错，给出引导性说明而不是空列表
- 系统时区或系统时间被回拨：不得因此重复弹窗、产生重复行动或倒退复习级别
- 系统时间被向前大幅跳过（如调整日期）：只为当天生成清单，不为中间跳过的日期补生成
- 提示窗口弹出时用户正在全屏使用其他程序（演示、游戏、视频）：不得抢占键盘焦点导致正在进行的输入被打断
- 多显示器或显示器被断开：提示窗口必须出现在当前可用的主屏幕上，不能落在已断开的屏幕之外
- 数据文件损坏或格式不符：启动时给出可执行的错误说明，不静默丢弃用户数据

## Requirements *(mandatory)*

### Functional Requirements

**目标与分类**

- **FR-001**: 用户 MUST 能创建、重命名、删除目标；目标至少包含名称与可选描述
- **FR-002**: 用户 MUST 能在目标下创建、重命名、删除分类；同一目标内的分类名称 MUST 唯一，不同目标之间允许重名
- **FR-003**: 用户 MUST 能按目标查看其下分类，按分类查看其下任务
- **FR-004**: 系统 MUST 拒绝空名称或仅含空白字符的名称，并按「哪一项输入不合法、期望什么、如何修正」给出说明，且失败时不得留下部分写入的数据
- **FR-005**: 删除目标或分类 MUST 先展示将被一并删除的分类、任务与未完成行动数量，确认后才执行；已完成的行动记录 MUST 保留

**任务与频率**

- **FR-006**: 用户 MUST 能在分类下创建、重命名、删除任务；任务至少包含名称与频率
- **FR-007**: 频率 MUST 至少支持三种形态：每天、每 N 天、每周 N 次
- **FR-008**: 系统 MUST 依据任务频率与上次生成行动的日期，判定某一日期是否需要为该任务生成常规行动，且判定规则对同一输入必须稳定可复现
- **FR-009**: 用户 MUST 能暂停与恢复任务；暂停期间该任务不产生常规行动与复习行动，恢复后不补生成暂停期间的行动

**每日行动生成**

- **FR-010**: 系统 MUST 能生成任一本地日期的行动清单，清单同时包含常规行动与复习行动，并标明每条行动的类型与所属分类
- **FR-011**: 同一日期、同一任务 MUST 最多生成一条行动；重复查看或重复生成 MUST 不产生重复项，且结果幂等
- **FR-012**: 每日行动总数 MUST 同时受两道上限约束：全局上限（默认 5 条，用户可调整）与每任务上限（本版固定为 FR-011 规定的每天 1 条，不提供调整）；两道上限任一被触及即截断，不因另一个上限还有空位而放宽
- **FR-013**: 待生成行动超过上限时，系统 MUST 按确定规则排序后截断，其余行动顺延到后续日期，并向用户显示顺延的数量
- **FR-014**: 排序规则 MUST 让复习行动优先于常规行动，同类型内按到期时间先后排列
- **FR-015**: 用户连续多日未使用系统时，系统 MUST 只生成当天可容纳的行动，不得一次性倾倒历史积压
- **FR-016**: 「今天」MUST 按用户本地时区与本地 00:00 日界计算；系统 MUST 在跨日后自动切换到新的一天

**完成、跳过与复习调度**

- **FR-017**: 用户 MUST 能将行动标记为已完成、跳过，并 MUST 能撤销最近一次标记
- **FR-018**: 行动被标记完成后，系统 MUST 依据遗忘曲线序列为该任务安排下一级复习日期
- **FR-019**: 复习行动被标记完成后，系统 MUST 将复习级别递增一级，并按序列安排再下一级复习日期
- **FR-020**: 跳过 MUST 不推进复习级别，也 MUST NOT 记为完成。被跳过的任务 MUST 继续参与之后的生成：复习行动因下次复习日未推进而在次日仍然到期，常规行动按频率决定下一次；系统 MUST NOT 因为一次跳过就把该任务从计划中永久移除
- **FR-021**: 系统 MUST 能让用户查看任一任务的复习进度：当前级别、下次复习日期
- **FR-022**: 用户 MUST 能重置某个任务的复习进度，重置后以最近一次完成行动的日期重新参与复习调度
- **FR-023**: 任务走完遗忘曲线序列后 MUST 标记为「已巩固」并停止自动生成复习行动，直到用户手动重置

**每日提示（常驻与置顶弹窗）**

- **FR-024**: 程序 MUST 以常驻方式运行；在同一个程序进程持续存活、电脑多天不关机的情况下，MUST 在每个本地日都触发一次提示，不依赖用户每天手动重启程序
- **FR-025**: 提示 MUST 以置顶窗口形式弹出到最前端，覆盖在其他普通窗口之上；窗口 MUST 展示当天未完成行动的数量，且 MUST NOT 抢占键盘焦点打断用户正在进行的输入
- **FR-026**: 同一本地日内提示窗口 MUST 最多弹出一次；用户关闭窗口即视为当天已提示，当天不再弹出
- **FR-027**: 用户当天已查看过今日清单后 MUST 不再弹出提示窗口
- **FR-028**: 当天没有未完成行动时 MUST 不弹出提示窗口，程序保持静默
- **FR-029**: 跨日时刻电脑处于睡眠、休眠，或程序被系统挂起时，程序 MUST 在恢复后立即补发当天的提示，且当天仍然只弹一次
- **FR-030**: 提示窗口 MUST 提供进入今日清单的入口，使用户可从提示直接看到行动并逐条标记完成
- **FR-031**: 程序退出后重新启动时，当天是否已提示的状态 MUST 保持；当天已提示过则 MUST NOT 再次弹窗

**通用**

- **FR-032**: 所有目标、分类、任务、行动、复习进度与提示状态 MUST 在程序退出后持久保留，重启后行为一致
- **FR-033**: 系统 MUST 在输入边界校验名称：限制长度上限，拒绝换行与控制字符，并在界面上转义不可信内容，避免破坏布局或伪造界面元素
- **FR-034**: 系统 MUST 让每一次数据变更类操作的失败原因可执行，且失败不得留下半完成状态
- **FR-035**: 系统 MUST 在完全空数据时仍能正常进入今日清单，给出引导而非错误

### Key Entities *(include if feature involves data)*

- **目标**: 一个长期方向（如「学习英语」）。包含名称、可选描述、创建时间；拥有零个或多个分类
- **分类**: 目标下的一类能力或主题（如语法、口语）。包含名称、所属目标；同一目标内名称唯一；拥有零个或多个任务
- **任务**: 一个可重复执行的最小单元（如「每周学习一个连读」）。包含名称、所属分类、频率（每天 / 每 N 天 / 每周 N 次）、状态（进行中 / 暂停）、最近一次生成行动的日期
- **行动**: 某一天的一条具体待办，由任务派生。包含所属任务、所属日期、类型（常规 / 复习）、复习级别（仅复习行动有）、状态（待办 / 已完成 / 已跳过 / 已顺延）、生成序号
- **复习进度**: 某个任务在遗忘曲线上的位置。包含所属任务、当前级别、下次复习日期、是否已巩固
- **提示记录**: 最近一次弹出提示的本地日期与当天清单的查看状态；用于判断当天是否还应弹窗，并在程序重启后延续

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户从空数据到「今天有一条可执行行动」，完整配置过程不超过 5 分钟，且无需查阅文档
- **SC-002**: 任意一天的清单条数 100% 不超过全局上限，且同一任务在一天内 100% 最多出现一条；超出的行动 100% 出现在后续日期的清单中，不丢失
- **SC-003**: 同一天内重复查看今日清单，结果 100% 一致；连续 30 天模拟运行后，行动与复习日期无重复、无遗漏
- **SC-004**: 被标记完成的行动，100% 在其遗忘曲线的下一个复习日出现在清单中，日期误差为 0 天
- **SC-005**: 用户每天了解「今天做什么」只需一次操作，呈现的行动条数不超过当天上限
- **SC-006**: 在单用户、200 个任务、连续运行 90 天的规模下，每日生成与查看行为保持一致，且不出现响应明显变慢的观察
- **SC-007**: 90% 的目标、分类、任务创建或修改操作在首次尝试即成功；失败时 100% 的错误信息能指出具体是哪个输入、期望规则与修正方式
- **SC-008**: 同一本地日内的提示窗口弹出次数不超过 1 次
- **SC-009**: 程序连续运行 15 天且中途不重启的情况下，100% 的每一天都恰好弹出一次提示窗口，无遗漏也无重复
- **SC-010**: 提示窗口 100% 显示在其他普通窗口之上，且在跨日后 5 秒内出现

## Assumptions

- **单用户、单机、本地使用**：不涉及账号体系、多设备同步与协作，无网络依赖
- **交互形态为 PC 桌面常驻程序**：程序由用户手动启动，启动后长期驻留后台并可按需打开主界面；移动端与网页端不在本规格范围内
- **提示走程序自己的置顶窗口**：不依赖操作系统通知中心，也不依赖终端输出
- **不提供开机自启与系统计划任务**：程序的存活依赖用户启动，本版不写注册表自启项、不注册系统服务
- **每天只提示一次**：用户关闭提示窗口即完成当天提示；不做重复催促、不做「未完成则再次提醒」
- **遗忘曲线采用固定间隔序列**：默认在第 1、2、4、7、15、30 天复习；具体天数可在实现时作为单一常量集中管理，本版不提供按任务自定义
- **走完序列即视为已巩固**：不再自动复习，避免无限续期；用户可手动重置
- **每日上限为双重约束**：全局上限默认 5 条且用户可调整；每任务上限为每天 1 条，与「同一任务每天最多一条行动」一致
- **每周 N 次的落地方式**：按「上次生成行动后至少间隔 ⌊7/N⌋ 天」判定，不要求用户指定具体星期几
- **不提供素材库 / 内容清单管理**：任务名即行动内容；需要内容递进时由用户更新任务名称
- **不提供统计报表与图表**：本版只保留完成记录，供后续按需扩展
- **数据保存在本地单个位置**，由用户自行备份；不涉及跨设备迁移与导入导出
- **提示只针对当天**，不做跨日堆积提醒
- **性能预算按桌面程序重新声明**：宪法第 V 条的 CLI p95 条款不适用于常驻桌面程序。本 feature 先在 plan 中以草案形式声明桌面预算（启动到可交互 p95 < 2s、跨日弹窗延迟 p95 < 5s、交互响应 p95 < 100ms、空闲 CPU p95 < 1%、常驻内存 p95 < 150MB、后台驻留内存 p95 < 80MB），实测数据到手后按治理条款以 MINOR 修订宪法第 V 条，目标版本 1.18.0（跟踪 issue：ngy-ai/ngy-min-action#1）
