# Feature Specification: 任务频率选择与复习进度展示

**Feature Branch**: `003-task-form-and-progress`
**Created**: 2026-11-03
**Status**: Draft
**Input**: 补齐 001 手工验收发现的两处缺口：新建任务没有频率选择，任务行不显示频率与复习进度。

**来源**: `specs/001-min-action-core/quickstart.md` 场景 1 第 3 步、场景 3 第 2 步的验收失败记录。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 创建任务时选择频率 (Priority: P1)

用户在分类下新建任务时可选「每天」「每 N 天」「每周 N 次」并填写参数，默认每天。提交后任务按所选频率入库，调度按该频率生成行动。

**Why this priority**: 没有频率选择就只能创建每天任务，模板里的三种频率能力在界面上形同虚设。

**Independent Test**: 同一分类下依次创建三个任务，分别选每天、每 3 天、每周 2 次，读回任务行的频率与所选一致；把「每 N 天」填成 0 或 366，提交被拒并提示范围。

**Acceptance Scenarios**:

1. **Given** 新建任务表单，**When** 不改频率直接提交，**Then** 任务按「每天」入库
2. **Given** 选择「每 N 天」填 3，**When** 提交，**Then** 入库为每 3 天，任务行显示「每 3 天」
3. **Given** 选择「每周 N 次」填 2，**When** 提交，**Then** 入库为每周 2 次，任务行显示「每周 2 次」
4. **Given** 选择「每 N 天」填 0 或 366，**When** 提交，**Then** 拒绝并说明「1 到 365 之间的整数」，不产生任务
5. **Given** 选择「每周 N 次」填 0 或 8，**When** 提交，**Then** 拒绝并说明「1 到 7 之间的整数」，不产生任务

---

### User Story 2 - 任务行显示频率 (Priority: P2)

用户扫一眼任务列表就能看出每个任务的节奏，不用点开详情。

**Why this priority**: 频率决定任务在每日清单里的出现频率，隐藏它会让用户误以为任务漏生成了。

**Independent Test**: 三种频率的任务分别显示「每天」「每 3 天」「每周 2 次」。

**Acceptance Scenarios**:

1. **Given** 一个每天任务，**When** 查看任务行，**Then** 显示「每天」
2. **Given** 一个每 3 天的任务，**When** 查看任务行，**Then** 显示「每 3 天」
3. **Given** 一个每周 2 次的任务，**When** 查看任务行，**Then** 显示「每周 2 次」

---

### User Story 3 - 任务行显示复习进度 (Priority: P1)

用户能看到任务在遗忘曲线上走到第几级、下次复习是哪天、是否已巩固，重置后立即回到未开始。

**Why this priority**: 001 的 T028 明确要求却未落地；看不到进度就无法判断复习是否按预期推进。

**Independent Test**: 完成一个任务后打开任务列表，显示「第 1 级」与次日日期；重置后显示「未开始」。

**Acceptance Scenarios**:

1. **Given** 从未复习过的任务，**When** 查看任务行，**Then** 显示「未开始」，不显示「第 0 级」或空白
2. **Given** 完成过 1 次复习的任务，**When** 查看任务行，**Then** 显示当前级别与下次复习日期
3. **Given** 已走完 6 级复习的任务，**When** 查看任务行，**Then** 显示「已巩固」，不再显示下次复习日
4. **Given** 已有复习进度的任务，**When** 点击「重置复习」，**Then** 任务行立即回到「未开始」

---

### Edge Cases

- **切换频率模式**：在「每 N 天」与「每周 N 次」之间切换时，参数输入保留上次填的值还是重置，需固定一种行为
- **参数为空或非数字**：与越界同样拒绝，不得写入
- **暂停中的任务**：仍显示频率与复习进度，暂停不影响既有进度的展示
- **已巩固任务的展示**：不显示下次复习日，避免误导用户以为还有复习安排
- **重置后展示**：必须与持久化状态同步，不能只在界面上清空

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 新建任务表单 MUST 提供「每天 / 每 N 天 / 每周 N 次」三种模式选择，默认每天
- **FR-002**: 「每 N 天」的参数 MUST 限定 1..=365 的整数，越界或非数字 MUST 拒绝并说明范围
- **FR-003**: 「每周 N 次」的参数 MUST 限定 1..=7 的整数，越界或非数字 MUST 拒绝并说明范围
- **FR-004**: 提交后任务 MUST 按所选频率入库，后续调度 MUST 按该频率生成行动
- **FR-005**: 任务行 MUST 显示人类可读的频率描述：每天 / 每 N 天 / 每周 N 次
- **FR-006**: 任务行 MUST 显示复习进度：当前级别、下次复习日期、是否已巩固
- **FR-007**: 没有复习记录的任务 MUST 显示「未开始」，MUST NOT 显示为第 0 级或留空
- **FR-008**: 已巩固的任务 MUST 显示「已巩固」，MUST NOT 显示下次复习日期
- **FR-009**: 重置复习进度后，任务行的展示 MUST 与持久化状态同步回到未开始
- **FR-010**: 本 feature MUST NOT 修改持久化结构；频率与复习进度均已存在于现有表中

### Key Entities

- **任务**: 频率三选一，参数受模式约束；已存在于 `tasks.freq_kind` / `freq_interval`
- **复习进度**: 级别、下次复习日、是否巩固；已存在于 `review_progress`
- **表单**: 新增的频率模式与参数输入，仅在创建任务时出现

## Success Criteria *(mandatory)*

- **SC-001**: 三种频率都能通过界面创建并正确入库，读回值与所选 100% 一致
- **SC-002**: 越界或非数字的频率参数 100% 被拒，且提示包含合法范围
- **SC-003**: 任务行的频率与复习进度展示与持久化状态 100% 一致，重置后立即反映

## Assumptions

- **不提供修改频率的入口**：001 没有「编辑任务频率」的需求，本 feature 只补齐创建时的选择
- **不新增领域逻辑**：频率判定与复习推进已实现，本 feature 只做界面接线与展示
- **复习进度按分类批量读取**：列表渲染需要一次性拿到该分类下全部任务的进度，避免逐条查询
- **日期按本地日期显示**：与今日清单的日期格式一致，不引入新的时间格式
- **不引入新依赖**：界面改动使用现有 `egui` 控件
