# Feature Specification: 任务行布局与误触防护

**Feature Branch**: `006-task-row-actions`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "真实跑一次 GUI 后，任务行太挤；重置复习没有确认，误点就丢进度。"

**背景**: 005 之后任务行排了 5 个控件（暂停/恢复、重置复习、频率、改名、×）。在默认 880 宽窗口、左侧树占 240 的情况下它们挤成一行，`×` 紧贴右边界；「重置复习」与「暂停」相邻且没有二次确认，误点会直接清空该任务的复习进度，且没有任何撤销入口。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 重置复习前二次确认 (Priority: P1)

用户点「重置复习」，先看到确认框说明当前级别与重置结果；确认后才真正清零，取消则一切不变。

**Why this priority**: 这是三个问题里唯一不可逆的：复习进度归零后无法恢复，而按钮与「暂停」只隔几像素。

**Independent Test**: 对一个第 2 级的任务点「重置复习」→ 弹窗显示「当前第 2 级」、任务进度不变；点「重置」→ 进度归零；点「取消」→ 进度仍为第 2 级。

**Acceptance Scenarios**:

1. **Given** 一个第 2 级任务，**When** 点「重置复习」，**Then** 弹窗说明当前级别与重置后果，此时数据未变
2. **Given** 上述弹窗，**When** 点「重置」，**Then** 该任务 level 归 0、下次复习日期清空，任务行显示「未开始」
3. **Given** 上述弹窗，**When** 点「取消」，**Then** 复习进度与任务行均不变
4. **Given** 弹窗打开期间切换左侧选中的分类，**When** 确认，**Then** 重置的仍是弹窗指向的原任务

---

### User Story 2 - 频率标签本身就是入口 (Priority: P2)

用户点任务行上的频率标签（`每天`／`每 3 天`／`每周 2 次`），直接打开改频率弹窗，不再需要单独的「频率」按钮。

**Why this priority**: 「频率」按钮与它左边的频率标签表示同一件事，重复占位；去掉后任务行少一个控件。

**Independent Test**: 任务行只剩 4 个控件（暂停/恢复、重置复习、改名、×）；点频率标签能打开弹窗且预填当前值。

**Acceptance Scenarios**:

1. **Given** 一个「每 3 天」的任务，**When** 点标签「每 3 天」，**Then** 打开改频率弹窗，预选「每 N 天」、参数为 3
2. **Given** 任务行，**When** 观察控件数量，**Then** 不再出现「频率」按钮

---

### User Story 3 - 删除入口与其余控件分隔 (Priority: P3)

任务行的 `×` 与「改名」之间留出可见间距，删除入口不再紧贴其他按钮。

**Why this priority**: 纯视觉，但影响误触与扫视效率；改动只需一处 `add_space`。

**Independent Test**: 任务行的 `×` 与「改名」之间有明显空隙，与目标行、分类行的处理一致。

**Acceptance Scenarios**:

1. **Given** 任意任务行，**When** 观察控件排布，**Then** `×` 左侧有间距，不与「改名」贴在一起

---

### Edge Cases

- **进度已是第 0 级**：确认框照常弹出，说明重置后仍是「未开始」
- **已巩固任务**（level 已走完序列、`graduated` 为真）：允许重置，重置后回到第 0 级并重新参与复习
- **重置失败**（任务已被删除）：弹窗保留，错误条说明原因
- **弹窗打开期间任务被删除**：确认时返回 `NotFound`，弹窗不关闭

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 「重置复习」MUST 先弹确认框，文案说明当前级别；确认前 MUST NOT 改动任何数据
- **FR-002**: 确认后 MUST 把该任务 `level` 归 0、`next_review_on` 清空、`graduated` 归 0
- **FR-003**: 取消 MUST 关闭弹窗且不改数据
- **FR-004**: 频率标签 MUST 可点击并打开改频率弹窗，预填当前模式与参数
- **FR-005**: 任务行 MUST 移除独立的「频率」按钮
- **FR-006**: 删除按钮 MUST 与其左侧控件之间留出间距
- **FR-007**: 暂停/恢复、改名、删除的既有行为 MUST NOT 改变

### Key Entities

- **复习进度**: `level`、`next_review_on`、`graduated`；重置即全部回到初始值
- **任务行控件**: 暂停/恢复、重置复习、改名、删除，共 4 个

## Success Criteria *(mandatory)*

- **SC-001**: 误点「重置复习」时，0 次直接改动数据（必须先确认）
- **SC-002**: 任务行控件从 5 个降到 4 个
- **SC-003**: 三类任务的频率标签点击后都能正确预填
- **SC-004**: 既有 17 条界面用例 100% 保持通过

## Assumptions

- **不提供撤销**：确认框已经承担防误触职责，不再加撤销栈
- **重置不清行动历史**：只改 `review_progress`，已完成的行动记录保留
- **间距只加在删除按钮前**：不重排整行，避免动到 004/005 的既有布局判断
