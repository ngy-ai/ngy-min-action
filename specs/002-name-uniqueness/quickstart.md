# Quickstart: 名称唯一性与规范化验收

**Feature**: `002-name-uniqueness`

## 自动化门禁

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
```

新增用例集中在 `tests/store_test.rs`，迁移用例需要先构造旧版本库文件再 `Store::open`。

## 场景 1：目标名称唯一（FR-001 / FR-003）

1. 创建目标「学习英语」
2. 再次创建「学习英语」

**预期**: 拒绝，提示「目标名称必须唯一：已存在名称「学习英语」，请换一个名称或先删除原有的那一项」，目标列表仍只有一条。

3. 创建「Learning English」，再创建「learning english」

**预期**: 第二次被拒；折叠后相同即视为重名。

4. 创建「  日语  」

**预期**: 成功，列表显示「日语」（两端空白已去除）。

## 场景 2：目标重命名冲突（FR-004）

1. 已有目标「学习英语」与「日语」
2. 把「日语」重命名为「学习英语」

**预期**: 拒绝，两个目标名称都不变。

## 场景 3：分类名称在同目标下唯一（FR-002）

1. 在「学习英语」下创建「口语」
2. 在同一目标下再次创建「口语」

**预期**: 拒绝，分类列表不变。

3. 在另一个目标「学日语」下创建「口语」

**预期**: 成功，两个同名分类分属不同目标。

4. 在同一目标下已有「语法」与「口语」时，把「语法」重命名为「口语」

**预期**: 拒绝，名称不变。

## 场景 4：删除不释放名称（FR-001 / FR-002）

1. 删除目标「学习英语」
2. 创建名为「学习英语」的新目标

**预期**: 拒绝创建。

3. 删除「学日语」下的分类「口语」，再在该目标下创建「口语」

**预期**: 拒绝创建。

> 该行为与 `001-min-action-core` 相反（001 中删除后允许重建同名）。001 的 `tests/store_test.rs` 里名为 `soft_deleted_category_disappears_from_lists` 的用例中含「删除后应允许重建同名分类」的断言，本 feature 需将其改为反向断言。

## 场景 5：升级清空（FR-008 / FR-009）

1. 用旧版本（`user_version = 1`）的数据库文件启动新版本

**预期**: 程序正常进入今日清单，目标、分类、任务、行动全部为空；每日上限回到默认的 5，即使升级前改过。

2. 新建若干数据后重启

**预期**: 数据保留，不再清空。

3. 构造一个无法升级的库（例如把库文件设为只读）

**预期**: 启动失败并给出可执行的错误说明，库文件内容不变，不存在「已清空但未建表」的中间态。

## 场景 6：Unicode 折叠反例

1. 创建目标「straße」，再创建「STRASSE」

**预期**: 第二次被拒（`ß` 折叠为 `ss`）。

2. 创建目标「ΣΟΦΟΣ」，再创建「σοφος」

**预期**: 第二次被拒（希腊字母大小写折叠）。
