# Quickstart: 重命名与任务删除验收

**Feature**: `004-edit-and-delete`

## 自动化门禁

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
```

## 场景 1：重命名目标（FR-001 / FR-002）

1. 创建目标「学习英语」
2. 点该目标的「改名」，输入框应预填「学习英语」
3. 改为「英语」并保存

**预期**: 左侧树显示「英语」，今日清单中的分类前缀同步变化。

4. 再建目标「日语」，把「日语」改名为「英语」

**预期**: 拒绝，提示目标名称必须唯一，弹窗保留。

## 场景 2：重命名分类（FR-003）

1. 在目标下创建「口语」与「语法」
2. 把「语法」改名为「口语」

**预期**: 拒绝，提示同一目标下的分类名称必须唯一。

3. 把「语法」改名为「语法练习」

**预期**: 成功，其下任务不受影响。

## 场景 3：重命名任务（FR-003）

1. 创建任务「连读」
2. 改为「连读练习」

**预期**: 任务行与今日清单同步显示新名称，频率与复习进度不变。

3. 在同一分类下再建「连读练习」，把其中一个改名为另一个的名称

**预期**: 允许，任务名无唯一性约束。

## 场景 4：删除任务（FR-005 / FR-006）

1. 创建一个今天有未完成行动的任务
2. 点该任务的「删除」

**预期**: 弹窗说明「会作废 N 条未完成行动」，此时任务仍在列表中。

3. 点「取消」

**预期**: 任务与行动均不变。

4. 再次点「删除」并确认

**预期**: 任务从列表消失，今日清单中对应行动显示「已过期」，待完成数量相应减少。

## 场景 5：边界

1. 把某个目标改名为它当前的名字

**预期**: 允许，不报错。

2. 打开重命名弹窗后，切换左侧选中的分类

**预期**: 弹窗仍指向原对象，保存后修改的是原对象。

## 通过标准

- 三条门禁全绿
- 场景 1–4 逐项符合预期
- `tasks.md` 全部勾选
