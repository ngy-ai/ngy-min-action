# Phase 1 Contract: 重命名弹窗与任务删除确认

**Feature**: `004-edit-and-delete` | **Date**: 2026-11-04

## Store

```rust
/// 某任务尚未结算的行动数量（`pending` 与 `deferred`）。
///
/// 用于删除确认弹窗说明影响范围；已结算的行动不计入。
///
/// # Errors
///
/// 读写失败时返回 `DomainError::Store`。
pub fn task_open_actions(&self, task: TaskId) -> Result<usize, DomainError>;
```

**契约**:

- 只统计 `status IN ('pending', 'deferred')`，不含 done / skipped / expired
- 任务不存在或已删除时返回 0，不视为错误（确认弹窗仍可展示）
- 纯只读，不修改任何状态

## 界面交互

### 重命名

| 对象 | 入口 | 校验 |
| --- | --- | --- |
| 目标 | 目标行的「改名」按钮 | `rename_goal`：名称合法性 + 全局唯一 |
| 分类 | 分类行的「改名」按钮 | `rename_category`：名称合法性 + 同目标唯一 |
| 任务 | 任务行的「改名」按钮 | `rename_task`：仅名称合法性 |

- 弹窗标题分别为「重命名目标」「重命名分类」「重命名任务」
- 打开时输入框预填当前名称并全选，便于直接覆盖
- 提交与取消按钮文案与新建弹窗一致：「保存」「取消」
- 失败时弹窗保留、输入保留，错误条在顶部显示
- 成功后弹窗关闭并刷新列表

### 任务删除

1. 任务行「删除」按钮 → 读取 `task_open_actions`
2. 弹出确认框：`删除任务「连读」会作废 3 条未完成行动，确定删除吗？`，按钮为「删除」「取消」
3. 确认 → `delete_task` → 刷新；取消 → 关闭弹窗，不做任何修改

**边界**:

- 弹窗打开期间切换左侧选中的分类，弹窗继续指向原任务
- 任务已无未完成行动时，文案为 `会作废 0 条未完成行动`

## 错误文案

沿用既有 `DomainError` 渲染：

- 重名：`目标名称必须唯一：已存在名称「学习英语」，请换一个名称或先删除原有的那一项`
- 空名称：`目标名称 不合法：不能为空或只含空格，请填写名称`
- 超长：`分类名称 不合法：长度超过上限 80 个字符，请缩短后重试`
