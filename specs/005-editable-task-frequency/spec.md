# Feature Specification: 任务频率可修改

**Feature Branch**: `005-editable-task-frequency`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "任务建成后频率无法修改，只能删了重建，连带作废当日行动与复习进度。"

**背景**: 003 让新建任务时可以选择「每天 / 每 N 天 / 每周 N 次」，但保存后这三个值就固定了。频率选错或计划变化时，唯一出路是删掉任务重建——按 004 的删除语义，这会作废该任务所有未完成行动，复习进度也一并丢失。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 修改任务频率 (Priority: P1)

用户在任务行点「频率」，弹窗预选当前模式与参数；改成新频率并保存后，任务行立即显示新频率，任务状态、名称与复习进度都不变。

**Why this priority**: 频率是任务唯一的调度参数，选错就等于这个任务每天都在错误的时间出现；不能改就只能重建，代价是所有历史行动与复习进度。

**Independent Test**: 把「连读」从「每天」改为「每 3 天」，任务行显示「每 3 天」，其复习进度等级与已完成行动数量不变。

**Acceptance Scenarios**:

1. **Given** 一个每天任务，**When** 点「频率」并改为「每 3 天」后保存，**Then** 任务行显示「每 3 天」，名称、状态、复习进度均不变
2. **Given** 频率弹窗，**When** 打开时，**Then** 模式与参数预选为该任务的当前值
3. **Given** 频率弹窗，**When** 参数留空、为 0 或超过上限，**Then** 拒绝并说明取值范围，弹窗与输入保留
4. **Given** 一个已暂停的任务，**When** 改频率，**Then** 允许保存，任务仍为暂停状态

---

### User Story 2 - 改频率后当日清单照常推进 (Priority: P2)

用户把低频任务改成高频（例如「每周 1 次」改成「每天」）后，不需要重建任务，下一次刷新就按新频率决定是否生成行动。

**Why this priority**: 改完频率如果当天清单不跟着走，用户会以为没生效而重复操作；但它不改变已有行动的语义，所以低于 US1。

**Independent Test**: 把昨天生成过行动的「每周 1 次」任务改成「每天」，跨日后刷新，今日清单出现该任务的新行动；改动当时，当天已存在的行动一条都不少。

**Acceptance Scenarios**:

1. **Given** 昨天有行动的每周任务，**When** 改成每天并跨日刷新，**Then** 今日清单按新频率生成行动
2. **Given** 今天已有行动的任务，**When** 只改频率不做跨日，**Then** 今天的行动既不新增也不删除
3. **Given** 一个任务，**When** 把频率从高频改为低频，**Then** 已经生成的行动仍然保留，只是下次生成被推迟

---

### Edge Cases

- **改频率为当前值**：不视为冲突，允许保存且不报错
- **弹窗打开期间切换分类**：弹窗继续指向原任务
- **暂停中的任务**：允许改频率，但暂停期间仍不生成行动
- **当天已生成行动后再改频率**：不追溯、不撤回、不重复生成
- **保存失败**：弹窗与输入保留，数据不变

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 任务行 MUST 提供改频率入口，弹窗 MUST 预选该任务的当前模式与参数
- **FR-002**: 弹窗 MUST 提供与新建任务表单相同的三种模式：每天、每 N 天、每周 N 次
- **FR-003**: 参数校验 MUST 与新建任务一致（每 N 天为 1 到上限的整数，每周 N 次为 1 到上限的整数）；不合法时 MUST 拒绝且保留弹窗与输入
- **FR-004**: 保存 MUST 只更新任务的频率字段，MUST NOT 改动任务名称、状态与复习进度
- **FR-005**: 改频率 MUST NOT 删除、改写或补生成任何已存在的行动
- **FR-006**: 下一次生成行动时 MUST 按新频率判定是否到期
- **FR-007**: 本 feature MUST NOT 修改持久化结构
- **FR-008**: 暂停中的任务 MUST 允许改频率

### Key Entities

- **任务频率**: 模式（每天 / 每 N 天 / 每周 N 次）与参数值；决定两次生成之间的间隔天数
- **任务**: 频率是其唯一的调度属性；改频率不影响名称、状态与复习进度

## Success Criteria *(mandatory)*

- **SC-001**: 三种模式之间任意转换都能保存成功，任务行标签 100% 同步
- **SC-002**: 非法参数 100% 被拒，被拒后任务数据不变
- **SC-003**: 改频率后，已存在的行动 0 条被删除或改写
- **SC-004**: 从低频改为每天后，下一个该生成行动的日子按新频率生成

## Assumptions

- **不提供「立即重算今天」**：改频率只影响下一次生成，与暂停/恢复的既有语义一致
- **不做频率变更历史**：只保留当前值，与 001 的数据模型一致
- **不新增任务数量或频率上限**：沿用 001 与 003 的既有边界
