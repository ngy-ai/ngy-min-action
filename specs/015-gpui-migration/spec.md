# 015 界面框架迁移到 gpui-kit

## 概述

当前界面层全部基于 `egui` / `eframe`（约 30 个源码文件、所有 `egui::Context` 无头测试）。
本特性将界面框架整体迁移到 [`gpui-kit`](https://github.com/longbridge/gpui-kit)（longbridge 出品，
基于 Zed 的 GPUI，Apache-2.0，当前 v0.9.1，提供 75+ 样式组件）。**数据层（`src/store`、`src/model`、
`src/attachment`）与框架无关，原样保留**，不改动 schema、存储与业务行为。

按用户决策，这是一次**全功能一次性迁移**：结构树（含计数）、任务/今日/历史三页签、所有对话框
（备注两栏、任务内容、重命名/删除/频率/耗时/存储/统计）、富文本与媒体渲染，全部迁到 gpui-kit，
并与现有 egui 版本保持功能等价。

## 用户故事

### US1：在 gpui-kit 应用里用回全部现有功能

- 左侧「目标与分类」树：显示目标/分类，分类行带任务数、目标行汇总其全部分类任务数（即 014 的计数）。
- 中央区三个页签：**任务 / 今日待办 / 历史待办**（即 014 的三页签）。
- 任务页：新建任务（名称/耗时/频率）、任务列表、任务内容编辑（标题+描述+图片/音频/视频附件，即 013）。
- 今日待办：今日最小行动列表，完成/跳过/撤销，备注入口（备注弹窗左右两栏展示来源任务，即 013）。
- 历史待办：分页加载的历史行动与结算。
- 工具栏（每日上限、主题、统计入口）、菜单栏、状态栏保留。

### US2：启动与交互体验不退化

- 应用以 gpui-kit 入口启动并渲染主窗口；主题、菜单、状态栏保留。
- 启动到可交互 p95 < 1s（沿用宪法桌面 GUI 预算，见 plan 性能一节）。

## 成功标准

- SC-1：`Cargo.toml` 移除 `eframe` / `egui_extras`，引入 `gpui-kit`；应用以 gpui-kit 入口启动并渲染主窗口。
- SC-2：现有全部 UI 功能在 gpui-kit 下等价实现（功能清单逐项对照，见 tasks.md 各阶段任务）。
- SC-3：现有基于 `egui::Context` 的 headless 测试全部改写为 gpui-kit 测试并转绿（或等价覆盖），
  不再保留任何 `egui` 专属测试代码。
- SC-4：门禁全绿 —— `fmt --check`、`clippy -D warnings`、`test --all-targets --all-features`、
  `machete`、`audit`。
- SC-5：启动到可交互 p95 < 1s（宪法桌面 GUI 预算）。

## 范围外

- 不改动数据层、存储、schema migrate、业务行为；不新增业务功能。
- 不做功能增强（如新的富文本排版、新的对话框），仅做框架等价迁移。
- 不引入 egui 与 gpui 双框架共存；一次性切换。
