# Feature Specification: 结构树改用右键菜单

**Feature Branch**: `011-context-menu`

**Created**: 2026-11-06

**Status**: Draft

**Input**: User description: "红框中按钮去除了，改成右键菜单。"（截图红框为左侧「目标与分类」结构树中每个目标／分类行右侧的改名与删除图标按钮）

**背景**: 010 把结构树里的「改名」「删除」换成了图标按钮，但每行固定占两个按钮，目标与分类层级多时左侧空间被挤占，图标也缺少上下文。改为在名称上右键弹出菜单，行内只保留展开／折叠图标与名称，既节省横向空间，又让动作和对象一一对应。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 右键菜单执行改名与删除 (Priority: P1)

用户在目标或分类名称上右键，菜单出现「改名」「删除」，选择后与原来点击行内图标的结果完全一致。

**Why this priority**: 这是需求本身：去掉行内按钮后必须保留等效的操作入口。

**Independent Test**: 选中任一目标／分类，右键查看菜单两项；分别执行改名与删除，核对弹窗与二次确认。

**Acceptance Scenarios**:

1. **Given** 结构树已展开，**When** 在目标名称上右键，**Then** 出现含「改名」「删除」的菜单
2. **Given** 已打开菜单，**When** 选择「改名」，**Then** 打开与原图标按钮相同的重命名弹窗，草稿为当前名称
3. **Given** 已打开菜单，**When** 选择「删除」，**Then** 进入原有的删除二次确认，不直接删除
4. **Given** 在分类名称上右键，**When** 选择两项动作，**Then** 作用于该分类而非其所属目标

---

### User Story 2 - 行内按钮移除且原有交互不退化 (Priority: P2)

结构树的目标／分类行不再显示改名与删除图标；左键单击名称仍选中该项，展开／折叠图标与其他区域的图标按钮保持不变。

**Why this priority**: 去掉按钮是本需求的另一半；不能为了腾空间破坏既有选择行为。

**Independent Test**: 逐行对照截图，确认红框内按钮消失；左键选中、展开／折叠、任务行与今日清单的图标按钮逐一验证。

**Acceptance Scenarios**:

1. **Given** 结构树已展开，**When** 查看目标／分类行，**Then** 只有展开／折叠图标与名称，没有改名与删除图标
2. **Given** 未展开右键菜单，**When** 左键单击名称，**Then** 仍选中该目标／分类，右侧任务区随之刷新
3. **Given** 顶栏、任务行与今日清单，**When** 查看图标按钮，**Then** 与 010 一致，没有连带改动
4. **Given** 名称控件，**When** 鼠标悬停，**Then** 给出「左键选中，右键菜单」之类的提示，让用户知道新入口

---

### User Story 3 - 菜单在两套主题下可读 (Priority: P3)

右键菜单沿用 009 的语义色与令牌，浅色／深色下文字清晰，删除项与普通项可区分。

**Why this priority**: 主题是刚建立的能力，新增菜单不能破坏；但相比前两项属于质量约束。

**Independent Test**: 浅色与深色各打开一次菜单，检查文字、背景与危险色。

**Acceptance Scenarios**:

1. **Given** 浅色或深色主题，**When** 打开右键菜单，**Then** 两项文字清晰可读、背景与界面一致
2. **Given** 任一主题，**When** 查看「删除」，**Then** 使用语义危险色，与「改名」可区分
3. **Given** 切换主题，**When** 再次打开菜单，**Then** 菜单配色随主题变化

---

### Edge Cases

- **右键空白区域**：只有名称控件响应右键，行内空白不弹菜单
- **折叠状态的分类**：分类未显示时不可操作，不存在误触发
- **菜单打开时左键**：菜单应关闭，左键仍完成选中
- **删除二次确认**：不能因为入口变成菜单而绕过
- **删除目标时含分类**：沿用原有影响提示与确认流程
- **深色主题**：删除项不能在深色背景上失去对比度
- **无目标时**：空状态提示仍是文字，不出现空菜单

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 结构树的目标／分类行 MUST NOT 再显示行内「改名」「删除」图标按钮
- **FR-002**: 在目标／分类名称上右键 MUST 弹出菜单，含「改名」「删除」两项
- **FR-003**: 菜单动作 MUST 与原图标按钮完全一致；「删除」MUST 保留二次确认
- **FR-004**: 左键单击名称 MUST 仍选中目标／分类，行为不变
- **FR-005**: 展开／折叠图标、顶栏图标、任务行与今日清单图标按钮 MUST 保持不变
- **FR-006**: 名称控件 MUST 提供悬停提示，说明右键可用
- **FR-007**: 菜单 MUST 在浅色与深色主题下可读；「删除」MUST 使用语义危险色
- **FR-008**: 菜单项 MUST 集中定义，便于测试与逐项核对
- **FR-009**: 移除动作后不再有消费者的图标映射项 MUST 一并删除，MUST NOT 留下死代码
- **FR-010**: 本 feature MUST NOT 改动业务数据、主题偏好、存储结构与调度逻辑
- **FR-011**: `Cargo.toml` MUST NOT 因本 feature 新增依赖

### Key Entities

- **结构树行**：目标或分类的名称控件，是右键菜单的触发区域
- **菜单动作**：改名、删除，与原有的重命名弹窗、删除确认一一对应
- **图标映射**：010 的 `ButtonId` 中仅删除目标／分类两项不再被使用

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 浅色与深色两套主题下各截图一次：结构树行内无改名／删除按钮，右键菜单出现且文字可读
- **SC-002**: 新增 headless 用例覆盖菜单项定义与两套主题渲染；既有全部测试保持通过
- **SC-003**: 左键选中、展开／折叠、任务行与今日清单图标按钮在替换前后行为一致
- **SC-004**: 无死代码、无 lint 抑制；`Cargo.toml` 无变化；`Color32::` 仍只在 009 的令牌文件

## Assumptions

- **范围**：仅截图中红框标出的结构树目标／分类行的改名与删除按钮；任务行、今日清单、顶栏与弹窗按钮保持 010 的原样
- **触发方式**：右键名称控件弹出菜单，左键仍为选中；不在行内空白处触发
- **菜单项形式**：用文字标签（菜单不是工具条按钮），「删除」使用语义危险色；这与 010 的图标化范围不冲突
- **可发现性**：名称控件增加一条悬停提示，不新增常驻说明文字，避免占空间
- **沿用机制**：继续复用 009 的语义色与 010 的图标控件，不新建配色或菜单框架
