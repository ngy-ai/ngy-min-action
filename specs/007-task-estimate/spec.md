# Feature Specification: 任务预计耗时

**Feature Branch**: `007-task-estimate`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "预计耗时这个字段一直有，但界面既不让人填也不显示，等于白存。"

**背景**: `estimated_minutes` 从 001 就在数据模型里，`create_task` 也接受它，但新建任务表单没有输入框、任务行不展示、建完也改不了。结果是这一列永远是 `NULL`，用户无法用耗时判断今天这 3 条行动要花多久。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看并修改任务耗时 (Priority: P1)

任务行在有估时时显示「25 分钟」，点击可改成别的值或清空；没有估时的任务行不显示多余占位。

**Why this priority**: 这是让字段真正可用的最小闭环：能看见、能改。

**Independent Test**: 给「连读」设 25 分钟 → 任务行出现「25 分钟」；改成 40 → 显示更新；清空 → 该段文字消失，其余信息不变。

**Acceptance Scenarios**:

1. **Given** 一个未估时的任务，**When** 观察任务行，**Then** 不出现任何耗时占位
2. **Given** 一个 25 分钟的任务，**When** 点「25 分钟」，**Then** 弹窗预填 25
3. **Given** 上述弹窗，**When** 改成 40 保存，**Then** 任务行显示「40 分钟」，频率、状态、复习进度不变
4. **Given** 上述弹窗，**When** 清空后保存，**Then** 任务行不再显示耗时
5. **Given** 弹窗中输入 `0`、`abc`、`481`，**When** 保存，**Then** 前两者视为清空或拒绝，`481` 必须被拒绝并保留弹窗

---

### User Story 2 - 新建任务时填耗时 (Priority: P2)

新建任务表单增加一个可选的耗时输入，留空即不估时。

**Why this priority**: 建任务时顺手填比建完再找回任务改更符合习惯；没有它，US1 的入口只能靠事后补。

**Independent Test**: 在新建表单填「名称 + 每 3 天 + 15 分钟」→ 添加后任务行显示「15 分钟」；留空添加 → 任务行无耗时。

**Acceptance Scenarios**:

1. **Given** 新建任务表单，**When** 只填名称和频率，**Then** 可以直接添加，任务无耗时
2. **Given** 新建任务表单，**When** 填 15 分钟后添加，**Then** 任务行显示「15 分钟」
3. **Given** 新建任务表单，**When** 填 481 后添加，**Then** 拒绝创建并说明取值范围

---

### Edge Cases

- **输入 0**：按「不估时」处理，与留空等价（`validate_estimated_minutes` 的既有语义）
- **最近一次估时被清空**：任务行回到无耗时的形态，不显示「0 分钟」
- **弹窗打开期间切换分类**：弹窗仍指向原任务
- **任务已被删除**：保存时返回 `NotFound`，弹窗保留
- **耗时超过一天上限**：480 分钟为上限，超出必须拒绝

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 有估时的任务行 MUST 显示该值，且 MUST 可点击打开编辑弹窗
- **FR-002**: 无估时的任务行 MUST NOT 显示耗时占位
- **FR-003**: 编辑弹窗 MUST 预填当前值，保存时 MUST 走 `validate_estimated_minutes`
- **FR-004**: 留空或输入 `0` MUST 视为清除估时
- **FR-005**: 新建任务表单 MUST 提供可选的耗时输入，校验规则与 FR-003 一致
- **FR-006**: 修改耗时 MUST NOT 影响频率、任务状态、复习进度与已生成的行动
- **FR-007**: 非法值 MUST 被拒绝并保留弹窗与输入，任务数据不变
- **FR-008**: 本 feature MUST NOT 修改持久化结构

### Key Entities

- **预计耗时**: 1 到 480 分钟的整数，或「未估时」；属于任务，不影响调度
- **任务**: 耗时是展示属性，改它不触发任何行动生成

## Success Criteria *(mandatory)*

- **SC-001**: 新建时填、事后改、清空三条路径都能保存，任务行 100% 同步
- **SC-002**: 非法值 100% 被拒，被拒后任务数据不变
- **SC-003**: 改耗时后，该任务的行动数、频率与复习进度 0 变化

## Assumptions

- **不在今日清单里汇总总耗时**：本期只做任务级展示，汇总留给统计页
- **不参与调度**：耗时只是信息，不改变「每天/每 N 天」的生成规则
- **不新增单位切换**：固定用分钟
